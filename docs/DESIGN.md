# Дизайн и гарантии

**Точка линеаризации.** Mutex защищает состояние, sequence и журнал. Операция строит отдельный снимок и дописывает его в журнал; только после append выполняет noexcept swap. При ошибке append объект становится poisoned: результат записи неоднозначен. После reopen полный валидный record применяется, оборванный хвост отбрасывается. Клиент перечитывает состояние.

**Token.** Поколение аренды равно sequence транзакции, сохранённому в журнале. Restart не возвращает старый token. ACK/NACK проверяют ID, статус, token и строгий срок. Истечение lease не останавливает внешний эффект старого обработчика: получателю нужна идемпотентность.

**Фрейм.** `checksum LQ1 sequence count [job fields...]\n`. Строки hex-кодированы, переносят нулевые байты и переводы строки. Проверяются checksum, версия формата, sequence, диапазоны и уникальность ключей. Последний record без newline незавершён; полный повреждённый record нельзя молча пропускать.

**Стоимость.** Submit/claim/ack/nack O(N+P), где P — общий размер payload. Память состояния O(N+P), replay хранит историю в памяти. Следующий шаг — потоковый replay, журнал переходов, checkpoint с атомарной заменой файла и fsync/FlushFileBuffers.

**Конкурентность.** Обработчик работает вне mutex. Lock-каталог исключает два FileJournal на одном пути при согласованном использовании. Путь должен быть каноническим и принадлежать приложению; симлинк-алиасы и внешнее редактирование вне модели. Один Journal нельзя разделять между несколькими Queue.
